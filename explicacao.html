Minimax — A IA que pensa na frente

🎮
Explicação simples
Imagine que você está jogando pedra-papel-tesoura e pode ver o futuro. Você pensa: "Se eu fizer pedra, meu adversário vai fazer papel e eu perco. Se eu fizer tesoura, ele faz pedra e eu perco de novo. Então eu faço papel — e mesmo que ele tente me vencer, o melhor que ele consegue é empatar."

O Minimax faz exatamente isso: a IA imagina todas as jogadas possíveis, imagina que o oponente vai sempre tentar prejudicá-la ao máximo, e escolhe o caminho que garante o melhor resultado possível mesmo no pior caso.

A = IA (MAX)  |  B = Oponente (MIN)  |  ● = movimentos disponíveis de A

A IA está em (2,2) e tem 6 movimentos possíveis. O Minimax vai simular cada um deles e perguntar: "Se eu for para lá, o que o oponente vai fazer? E aí o que eu posso fazer?"

1
A IA vai para (1,1) — bloqueando (5,4).
O oponente tem 5 movimentos. A IA fica com 7. Heurística = +2.
2
A IA vai para (3,3) — bloqueando (4,4).
O oponente fica com 3 movimentos. A IA fica com 6. Heurística = +3.
3
O Minimax escolhe ir para (3,3) porque mesmo supondo que o oponente jogue perfeitamente depois, esse caminho garante a maior vantagem mínima.

O nome Minimax vem de duas palavras: MIN (o oponente minimiza a pontuação da IA) e MAX (a IA maximiza a própria pontuação). Eles se alternam a cada nível da árvore de busca.

minimax_agent.py — explicação linha a linha
class MinimaxAgent:
Define o agente que usa o algoritmo Minimax.
def __init__(self, profundidade_maxima=3):
Cria o agente. O número 3 significa: "olha até 3 turnos à frente". Quanto maior, mais inteligente — mas mais lento.
self.profundidade_maxima = profundidade_maxima
Guarda até onde a IA vai olhar na árvore de jogadas.
self.INFINITO = float('inf')
Um número gigante que representa "o pior/melhor resultado imaginável". Usado como valor inicial de comparação.
def escolher_acao(self, estado_atual):
A função principal: recebe o tabuleiro atual e devolve a melhor jogada que a IA encontrou.
melhor_acao = None melhor_pontuacao = -self.INFINITO
Começa sem nenhuma escolha e com a pior pontuação possível. A cada jogada analisada, tenta melhorar.
for acao in estado_atual.get_acoes_legais():
Para cada jogada que a IA pode fazer agora (mover + bloquear), testa uma por uma.
proximo_estado = estado_atual.aplicar_acao(acao)
Simula o tabuleiro após essa jogada. Não mexe no tabuleiro real — é só uma cópia mental.
pontuacao = self._minimax(proximo_estado, self.profundidade_maxima - 1, jogador_esta_maximizando=False)
Chama o Minimax recursivo para ver quanto vale esse estado futuro. False = próximo turno é do oponente (MIN).
if pontuacao > melhor_pontuacao: melhor_pontuacao = pontuacao melhor_acao = acao
Se essa jogada é melhor do que tudo que viu antes, guarda ela como a nova melhor opção.
return melhor_acao
Devolve a melhor jogada encontrada depois de analisar todas as opções.
def _minimax(self, estado, profundidade, jogador_esta_maximizando):
A parte recursiva: avalia estados futuros alternando entre MAX (IA) e MIN (oponente).
if profundidade == 0 or estado.jogo_terminou():
Caso de parada: chegou no limite de visão (profundidade 0) ou o jogo acabou. Hora de medir quem está ganhando.
return self.avaliar(estado)
Chama a heurística: conta movimentos disponíveis e retorna um número que mostra quão boa é essa posição para a IA.
acoes_possiveis = estado.get_acoes_legais()
Lista todas as jogadas possíveis neste estado (para o jogador cujo turno é agora).
if jogador_esta_maximizando:
É o turno da IA? Então ela quer o MAIOR valor possível.
melhor_valor = -self.INFINITO for acao in acoes_possiveis: estado_filho = estado.aplicar_acao(acao) pontuacao_filho = self._minimax(estado_filho, profundidade-1, False) melhor_valor = max(melhor_valor, pontuacao_filho) return melhor_valor
Testa todas as jogadas da IA. Para cada uma, simula o estado resultante e chama o Minimax de novo — agora é a vez do oponente (False). Guarda a maior pontuação encontrada.
else:
É o turno do oponente? Ele quer o MENOR valor possível (prejudicar a IA ao máximo).
melhor_valor = self.INFINITO for acao in acoes_possiveis: estado_filho = estado.aplicar_acao(acao) pontuacao_filho = self._minimax(estado_filho, profundidade-1, True) melhor_valor = min(melhor_valor, pontuacao_filho) return melhor_valor
Testa todas as jogadas do oponente. Para cada uma, o Minimax continua — agora é a vez da IA (True). Guarda a menor pontuação (pior para a IA, melhor para o oponente).
Por que isso funciona? Porque a IA sempre assume o pior caso — que o oponente vai jogar perfeitamente. Assim, a IA nunca se surpreende: se o oponente jogar mal, a IA só se sai melhor do que esperava.

Poda Alfa-Beta — O Minimax que para de perder tempo

🛒
Explicação simples
Você quer comprar o tênis mais barato. Já foi na primeira loja e pagaria no máximo R$ 150. Entra na segunda loja, o vendedor mostra o primeiro tênis por R$ 200.

Você para de olhar o restante da loja. Não importa o que mais tem ali — nada será mais barato do que o que você já encontrou. Você sai e vai para a próxima loja.

O Alfa-Beta faz o mesmo: quando descobre que um caminho da árvore nunca vai ser melhor do que o que já encontrou, ele para de explorar esse caminho imediatamente.
Exemplo real no Isolation — quando a poda acontece
1
IA explora o ramo esquerdo: oponente vai para (3,1) e bloqueia (4,4).
A IA fica com 6 movimentos, oponente com 4. Heurística = +2.
→ Alpha da IA sobe para +2.
2
IA explora o ramo direito: oponente vai para (4,2) e bloqueia (1,1).
A IA fica com 4 movimentos, oponente com 6. Heurística = −2.
→ Beta do oponente cai para −2.
3
Beta (−2) ≤ Alpha (+2): PODA!
O oponente nunca escolheria este ramo porque a IA já garantiu +2 em outro caminho. Nem vale explorar os filhos restantes.
Resultado: a IA chegou na mesma decisão do Minimax puro, mas analisou menos da metade dos estados. No Isolation isso significa ir de profundidade 3 para profundidade 5 no mesmo tempo.
O que a IA NÃO precisa mais calcular:

B
✗ Este estado e todos os filhos dele foram cortados — a IA já sabe que o ramo esquerdo é melhor.
alpha_beta_agent.py — explicação linha a linha
class AlphaBetaAgent:
Versão melhorada do Minimax que evita explorar caminhos inúteis.
def escolher_acao(self, estado_atual):
Função principal: devolve a melhor jogada, igual ao Minimax — mas muito mais rápido.
melhor_acao = None alfa = -float('inf')
Alfa = a melhor pontuação que a IA já garantiu. Começa em −∞ (ainda não garantiu nada). Vai crescendo à medida que encontra boas jogadas.
beta = float('inf')
Beta = a melhor pontuação que o oponente já garantiu. Começa em +∞ (ainda não garantiu nada). Vai diminuindo à medida que o oponente encontra jogadas ruins para a IA.
for acao in estado_atual.get_acoes_legais(): proximo_estado = estado_atual.aplicar_acao(acao) pontuacao = self._alfa_beta(proximo_estado, self.profundidade_maxima - 1, alfa, beta, jogador_e_max=False)
Para cada jogada possível, simula o estado resultante e chama o Alfa-Beta recursivo passando os valores atuais de alfa e beta para baixo na árvore.
if pontuacao > alfa: alfa = pontuacao melhor_acao = acao
Se essa jogada é melhor do que a melhor que a IA já garantiu, atualiza alfa e guarda essa jogada como a melhor opção.
def _alfa_beta(self, estado, profundidade, alfa, beta, jogador_e_max):
A busca recursiva. Recebe alfa e beta como limites: qualquer valor fora dessa faixa pode ser ignorado.
if profundidade == 0 or estado.jogo_terminou(): return self.avaliar(estado)
Igual ao Minimax: se chegou no limite de visão ou o jogo acabou, usa a heurística para estimar o valor do estado.
if jogador_e_max:
É o turno da IA (MAX)? Ela quer o maior valor. A novidade aqui é o uso de alfa para cortar.
melhor_valor = -float('inf') for acao in estado.get_acoes_legais(): estado_filho = estado.aplicar_acao(acao) melhor_valor = max(melhor_valor, self._alfa_beta(estado_filho, profundidade-1, alfa, beta, False)) alfa = max(alfa, melhor_valor)
Explora os filhos e vai guardando o maior valor. Atualiza alfa: agora a IA garante pelo menos esse valor.
if beta <= alfa: break
PODA BETA: o oponente (que está num nível acima) já garantiu um valor ≤ beta. Se beta ≤ alfa, o oponente nunca deixaria a IA chegar aqui — ele já tem uma opção melhor para ele. Inutile continuar.
else: # turno do oponente (MIN)
É o turno do oponente (MIN). Ele quer o menor valor. A novidade é o uso de beta para cortar.
melhor_valor = float('inf') for acao in estado.get_acoes_legais(): estado_filho = estado.aplicar_acao(acao) melhor_valor = min(melhor_valor, self._alfa_beta(estado_filho, profundidade-1, alfa, beta, True)) beta = min(beta, melhor_valor)
Explora os filhos e vai guardando o menor valor. Atualiza beta: o oponente agora garante que a IA não vai passar disso.
if beta <= alfa: break
PODA ALPHA: a IA (que está num nível acima) já garantiu alfa. Se beta ≤ alfa, a IA nunca escolheria este caminho — ela já tem algo melhor. Não precisa continuar explorando.

Função Heurística — Como a IA mede quem está ganhando

🗺️
Explicação simples
Imagine que você está perdido numa cidade e quer chegar à estação de trem. Você não sabe o caminho exato, mas olha ao redor e pensa: "Estou num beco sem saída com só 2 ruas disponíveis. Meu amigo está numa praça aberta com 8 ruas."

Você conclui: seu amigo está em vantagem — ele tem muito mais opções do que você. No Isolation é a mesma coisa: quem tem mais movimentos disponíveis está em melhor posição, porque o objetivo é não ficar preso.

A heurística não prevê o futuro — ela tira uma foto do tabuleiro agora e diz um número: "quanto maior, melhor para a IA".

A heurística do nosso agente vai além de só contar movimentos imediatos. Ela usa quatro componentes combinados com pesos:

1. Mobilidade diferencial

Meus movimentos − movimentos do oponente. Quanto maior, melhor — significa que tenho mais espaço e liberdade.

2. Território (flood fill)

Conta quantas células cada jogador consegue alcançar ao longo do jogo, não só agora. Quem "controla" mais área do tabuleiro está em vantagem.

3. Centralidade (Chebyshev)

Distância do meu peão ao centro do tabuleiro. Ficar no centro dá mais opções de movimento — ficar no canto te prende mais fácil.

4. Isolamento do oponente

Distância de Chebyshev entre os dois peões. Quanto mais longe do oponente, mais isolado ele está — o que é bom para mim.

heuristic_agent.py — explicação linha a linha
PESOS = { 'mobilidade': 2.5, 'territorio': 1.2, 'centralidade': 0.8, 'isolamento': 1.5, }
Cada componente tem um peso diferente. Mobilidade vale mais (2.5) porque ter mais movimentos é o mais importante no Isolation. Centralidade vale menos (0.8) pois é apenas um bônus secundário.
def avaliar(self, estado):
Recebe um tabuleiro e devolve um número: positivo = IA está bem, negativo = IA está mal, ±infinito = fim de jogo.
eu = estado.jogador_ativo oponente = estado.jogador_inativo
Identifica quem é a IA e quem é o oponente neste estado específico (pode alternar dependendo da profundidade).
movimentos_proprios = len(estado.get_acoes_legais(eu)) movimentos_oponente = len(estado.get_acoes_legais(oponente))
Conta quantos movimentos cada jogador tem disponíveis agora. Se a IA tem 0, perdeu. Se o oponente tem 0, a IA ganhou.
if movimentos_proprios == 0: return float('-inf') if movimentos_oponente == 0: return float('+inf')
Estados terminais: se a IA ficou sem movimentos, retorna o pior número possível (derrota). Se o oponente ficou sem movimentos, retorna o melhor número possível (vitória).
diferenca_mobilidade = movimentos_proprios - movimentos_oponente
Componente 1: a diferença de movimentos. Se a IA tem 6 e o oponente tem 4, isso vale +2. Se a IA tem 3 e o oponente tem 7, vale −4 (ruim).
territorio_proprio = self._flood_fill(estado, eu) territorio_oponente = self._flood_fill(estado, oponente) diferenca_territorio = territorio_proprio - territorio_oponente
Componente 2: usa flood fill (uma inundação virtual a partir de cada peão) para contar quantas células cada um consegue alcançar. Quem alcança mais células "controla" mais território.
centro_linha, centro_col = estado.tamanho // 2, estado.tamanho // 2 minha_linha, minha_col = estado.get_posicao(eu) distancia_ao_centro = self.chebyshev( (minha_linha, minha_col), (centro_linha, centro_col) ) bonus_centralidade = -distancia_ao_centro
Componente 3: calcula a distância de Chebyshev do meu peão ao centro do tabuleiro (3,3 num tabuleiro 7×7). Mais perto = melhor, por isso o sinal negativo: distância 0 dá bônus 0, distância 3 dá penalidade −3.
isolamento_oponente = self.chebyshev(minha_posicao, posicao_oponente)
Componente 4: distância de Chebyshev entre os dois peões. Quanto mais longe do oponente, mais isolado ele está. Útil especialmente no final do jogo quando o tabuleiro está cheio de bloqueios.
return ( self.PESOS['mobilidade'] * diferenca_mobilidade + self.PESOS['territorio'] * diferenca_territorio + self.PESOS['centralidade'] * bonus_centralidade + self.PESOS['isolamento'] * isolamento_oponente )
Score final: soma os quatro componentes cada um multiplicado pelo seu peso. Ex: mobilidade +2 × 2.5 = 5.0, território −1 × 1.2 = −1.2, centralidade −1 × 0.8 = −0.8, isolamento +3 × 1.5 = 4.5 → total = +7.5.
def chebyshev(self, posicaoA, posicaoB):
Função auxiliar que calcula a distância de Chebyshev: o mínimo de passos de rei para ir de A até B.
diferenca_linhas = abs(posicaoA[0] - posicaoB[0]) diferenca_colunas = abs(posicaoA[1] - posicaoB[1]) return max(diferenca_linhas, diferenca_colunas)
Calcula a diferença de linhas e colunas entre os dois pontos e retorna o maior dos dois. Ex: de (1,1) até (4,5) → linhas: |4−1|=3, colunas: |5−1|=4 → max(3,4) = 4 passos de rei.
def _flood_fill(self, estado, jogador):
Conta as células que o jogador consegue alcançar partindo da sua posição atual, usando BFS (busca em largura).
posicao_inicial = estado.get_posicao(jogador) celulas_visitadas = {posicao_inicial} celulas_para_explorar = [posicao_inicial]
Começa na posição do jogador. celulas_visitadas evita contar a mesma célula duas vezes. celulas_para_explorar é a fila de próximas células a verificar.
while celulas_para_explorar: linha_atual, col_atual = celulas_para_explorar.pop()
Enquanto houver células para explorar, pega a próxima da fila e verifica todos os vizinhos ao redor (as 8 direções do rei).
for delta_linha, delta_col in DIRECOES_REI: nova_linha = linha_atual + delta_linha nova_col = col_atual + delta_col nova_pos = (nova_linha, nova_col) if nova_pos not in celulas_visitadas: if estado.posicao_valida(nova_pos): celulas_visitadas.add(nova_pos) celulas_para_explorar.append(nova_pos)
Para cada uma das 8 direções, verifica a célula vizinha. Se ainda não foi visitada e está dentro do tabuleiro e livre, adiciona à lista para explorar — como uma inundação se espalhando pelo tabuleiro.
return len(celulas_visitadas)
Retorna o número total de células que o jogador consegue alcançar. Quanto maior, mais espaço ele tem no tabuleiro.
A heurística não é perfeita — ela é uma estimativa. Mas no Isolation ela funciona muito bem porque mobilidade e território são os fatores que realmente decidem o jogo: quem fica preso primeiro perde.
